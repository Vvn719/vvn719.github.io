# 正式使用前檢查清單

每次正式點名前，建議依序完成本清單。若其中一項失敗，先暫停正式點名，完成修正與備份後再開始。

## 部署與版本

- [ ] GitHub Pages 是否已部署最新版本。
  - 開啟 `https://vvn719.github.io/`。
  - 確認右上角有學期選單、管理、設定 API、同步按鈕。
  - 若剛 push，請等待 GitHub Pages 更新後再測。
- [ ] Apps Script 是否已重新部署。
  - Apps Script 修改後必須「部署」新版 Web App。
  - 只按儲存不等於正式 API 已更新。
- [ ] API URL 是否為最新 `/exec`。
  - 網站右上角「設定 API」內的 URL 必須是 Apps Script Web App `/exec` URL。
  - 不使用 `/dev`、編輯器網址或舊部署網址。
- [ ] 確認瀏覽器不是吃到舊版快取。
  - 若修改過 `app.js`，確認 `index.html` 的 `app.js?v=...` 已更新。

## 使用者端測試

- [ ] 無痕模式測試。
  - 使用無痕視窗開啟 GitHub Pages。
  - 確認可以自動載入學期、課程、學生。
  - 確認右上角同步狀態最後顯示 `已同步`。
- [ ] 手機測試。
  - 用手機開啟 GitHub Pages。
  - 測試搜尋、勾選卡片、快速跳組、送出按鈕、匯出按鈕是否可操作。
  - 確認底部 sticky 按鈕沒有遮住重要內容。
- [ ] 送出報到測試。
  - 選擇正式使用的學期與課程。
  - 用一筆可接受的測試資料做出席、遲到、請假或不列入出席測試。
  - 送出後確認右上角狀態為 `已同步`。
- [ ] Google Sheet `attendance` 是否有寫入。
  - 回到 Google Sheet 的 `attendance` 工作表。
  - 確認剛剛測試的 `semesterId`、`classId`、`studentId`、`status`、`note` 有新增或更新。
  - 確認沒有誤刪其他學期紀錄。
- [ ] Excel 匯出測試。
  - 按「匯出 Excel」。
  - 打開檔案，確認課程欄位、符號、請假原因、各組統計與全班統計正確。
  - 符號規則：`V` 出席/線上、`/` 遲到、`X` 請假、`△` 不列入出席。

## 管理模式測試

- [ ] 管理模式 CSV 匯入測試。
  - 開啟右上角「管理」。
  - 使用「學生 CSV」或「課程 CSV」先做預覽。
  - 確認必要欄位、筆數、錯誤提示都正確。
  - 正式匯入前請先完成 Google Sheet 備份。
- [ ] 複製學期測試。
  - 在「管理」的學期管理中選擇來源學期。
  - 輸入新的 `semesterId` 與名稱。
  - 確認預覽顯示學生與課程筆數。
  - 確認複製後新學期可以切換、同步，且不含舊學期 attendance。

## 安全備份

- [ ] 正式點名前已完成 Google Sheet 備份。
  - 建議直接複製整份 Google Sheet。
  - 或依 [backup.md](./backup.md) 建立工作表層級備份。
- [ ] 備份檔案名稱含日期與用途。
  - 例：`34期出缺席紀錄-正式點名前備份-2026-05-08`。
